# Snake / Linear Draft — Architecture Map

Covers both `draftType` values `"snake"` and `"linear"` — they share every schema field and function below; `reversalRounds` (only meaningful for `"snake"`) is what makes a round bounce back an extra time (3rd-round-reversal style) instead of just alternating.

Committed to git (unlike `SNAKE_DRAFT.md`/`YAHOO.md`/etc.) so every worktree/checkout has it automatically. Companion to [AUCTION.md](AUCTION.md). Read this file before researching or changing snake/linear-specific code; check both files' "Shared" sections for anything that touches `draftPicks`, team management, keeper rules, Sleeper/Yahoo sync, or league settings.

Format is resolved via `resolveDraftType(season, draft)` in `convex/draftType.ts` (see [AUCTION.md](AUCTION.md) for the exact resolution order — auction is the fallback). Snake/linear is opt-in, gated behind `VITE_ENABLE_SNAKE_DRAFT` in `src/lib/featureFlags.ts` — but that flag **only hides the Settings draft-type selector**; every downstream code path (schema fields, Convex functions, components) is fully reachable once a season's `draftType` is actually set to `"snake"`/`"linear"`.

## Convex schema (snake/linear-only)

- `drafts.draftOrder` — the real, **authoritative** round-1 pick order (array of `seasonTeams` ids). Distinct from auction's `nominationOrder` even though both step through the same rotation math.
- `drafts.reversalRounds` — rounds where the snake bounce additionally reverses. Meaningless for `"linear"` (no bounce at all) or auction.
- `draftPicks.round` / `pickInRound` / `overallPick` — stored explicitly (not derived from `sequence`), because traded/forfeited slots break the "sequence = slot number" assumption
- `draftPickSlots` (whole table) — lazily-created per `(draftId, round, originalTeamId)` row recording a trade, forfeit, or round-based-keeper claim (`currentTeamId: null` = forfeited). No auction equivalent — auction has no slot concept to trade or forfeit.
- `seasons.keeperRules.costMode: "round"` + `defaultRoundFormula` + `tiers[].roundFormula` + `roundConflictResolution` (`"earlier"|"later"`) — active when `costMode === "round"`

## Convex functions (snake/linear-only)

- **`convex/draft/pickSlots.ts`** (whole file): `slotKey`, `countForfeitedByRound`, `forfeitedPositions`, `filledPositions`, `findNextOpenSlot` (shared "first open (round,position)" scan — used both when a live pick is made and by the board's on-clock display), `resolveRoundConflict` (walks toward the configured direction to find a team's nearest open round when two keepers collide), `countRealSlotsThroughRound`, `listPickSlots`, **`getSnakeBoardPublic`** (fully server-resolved round×team grid powering the TV board — position-in-round, trade/forfeit overrides, who's on the clock, all computed server-side per this codebase's convention that round/position math never gets duplicated client-side), `tradePickSlot`, `forfeitPickSlot`, `restorePickSlot`. Trade/forfeit aren't explicitly `draftType`-gated — they're implicitly protected because `draft.draftOrder` is normally unset for auction leagues.
- **`convex/draft/draftOrder.ts`** (whole file): `getDraftOrderConfig(Public)`, `setReversalRounds`, `setDraftOrder`, `randomizeDraftOrder` (Fisher-Yates), `clearDraftOrder` — all locked to pre-draft (`requireDraftNotStarted`), since a real snake/linear order is authoritative (unlike auction's soft nomination order). `setDraftOrder`/`randomizeDraftOrder`/`setReversalRounds` all funnel their order/reversal-rounds change through `reconcileKeeperSlots`, which recomputes every existing round-based keeper's `pickInRound`/`overallPick` via `resolveTeamPositionInRound` (keeper `round` itself is untouched — it's chosen by the cost formula, not team order) - without this, a keeper set before a reorder would silently point at the wrong slot/team column afterward.
- **`convex/draft/picks.ts`**'s **`draftPick`** — the direct "team X takes player Y" mutation (no nomination/bid to consume); computes `round`/`pickInRound`/`overallPick` via `findNextOpenSlot`, advances the shared `draftNominationTurns` pointer via `stepPickOrder`. The **only** function in the auction/snake split that explicitly throws if `resolveDraftType(...) === "auction"`.
- **`convex/draft/picks.ts`**'s **`setKeeperRound`** — round-based counterpart to `setKeeperPrice`; explicitly throws if the season is auction-typed.

## Frontend (snake/linear-only)

- `/league/$leagueId/draft` → `src/pages/DraftRoom/SnakeDraftTab.tsx` (dispatched when `draftType !== "auction"`) — self-contained on-the-clock flow: "picking as" team selector, available-players table (search/position filter, sortable Rank/ADP/Pts columns — **no `dollarValue` anywhere**), recent-picks table showing `round.pickInRound` instead of price, "Undo last pick". The available-players table's own overall Rank (`lib/valueRank.ts`'s `buildOurRankByFpid`, same numbers `PlayersTable.tsx`/`PlayersLeftTab.tsx` use) is its own leading column - **not** combined with the "vs ADP" diff into one cell the way `AdpValueLabel.tsx` does elsewhere (user feedback, 2026-08-30: rank and vs-ADP should each be their own plain, independently-sortable column here, Rank first before Player - this table doesn't reuse `AdpValueLabel` at all). Before the 2026-08-30 fixes this showed `row.positionRank` (per-position, not comparable across positions) mislabeled "Rk" and was fixed-sorted by points with no way to change it.
- `src/pages/DraftRoom/components/MobileSnakeDraft.tsx` — the mobile "draft a player" FAB + bottom sheet, snake/linear's counterpart to auction's `MobileNomination`, and (per that same 2026-08-30 report) the primary mobile drafting surface - same column layout and fix as `SnakeDraftTab.tsx` above (Rank first, then Player, ADP, Pts, vs ADP; sortable Rank/ADP/Pts; wrapped in a `Table.ScrollContainer` now that it's 6 columns wide). Mounted at the layout level (`route.tsx`, `isStarted && !isAuction`) rather than inside the Draft tab, so a pick can be made from any tab; hides itself above `"sm"`, where `SnakeDraftTab`'s inline table is the path instead. Shows a `round.pickInRound, overall/total` pick line (e.g. "1.01, 1/192"), a team-chip row for "picking as" that calls out the on-the-clock team, and the same available-players table + Draft buttons. Self-querying (no snake analog of `DraftTopBar` to thread props from); Convex dedupes the identical subscriptions it shares with `SnakeDraftTab`. Reads `getSnakeBoardPublic` for on-the-clock/pick numbering, same as the TV board — never re-derives round math client-side.
- `src/pages/DraftRoom/components/mobileDraftSheet.tsx` — **shared with auction**: `DraftFab` (the BottomNav-notch circle), `BottomSheet` (swipe-dismissable Drawer + its z-index/blur/drag chrome), and `TeamChipRow`. Both `MobileNomination` and `MobileSnakeDraft` render through these, so the fiddly FAB/drawer geometry lives in one place.
- `/board/$leagueId` → `src/pages/DraftBoard/SnakeDraftBoard.tsx` (dispatched from `DraftBoard.tsx` when `!isAuction`) — round-by-round TV board: one column per team, one row per round, snake-bounce arrows, on-the-clock pulse, traded/forfeited-slot badges, "JUST DRAFTED" ticker flash, "UP NEXT" queue. Built from a Claude Design mockup ("Infinidraft UX review" project, `Snake Draft TV Board.dc.html`) — deliberately dropped the mockup's simulated countdown clock since no timer schema/mutation exists anywhere in this app; full provenance notes in `SNAKE_DRAFT.md` §5.2 (gitignored, not synced automatically across worktrees — resync manually if working from a different worktree).
- `src/pages/Settings/components/PickSlotsPanel.tsx` — "Traded & Forfeited Picks" editor, pre-draft only (`isDraftStarted` prop)
- Reversal-rounds config + Draft Order mode inside `TeamsPanel.tsx` (`isSnakeOrLinear` branch): panel title becomes "Draft Order", edits `setDraftOrder`/`clearDraftOrder` instead of `setNominationOrder`/`clearNominationOrder`, hides the Linear/Snake mode toggle (implied by `draftType` itself) and per-team salary-cap editing
- Round-based keeper cost UI: `KeeperRulesPanel.tsx` (round-formula fields — `roundsEarlier`/`minimumRound`/`undraftedRound` — + `roundConflictResolution` control, snake/linear only), `src/lib/keeperCost.ts`'s `computeKeeperCostRound`/`roundFormulaForFpid`/`valueImpliedRound`/`expectedValueAtRound`/`sortValuesDescending` (ranks a keeper bargain by the player's own `dollarValue` against a pooled rank-based "expected value at this round" curve — avoids both round-linearity and ADP position-run distortion — still displayed to the user as "+N rounds")

## Shared / must maintain both

**Schema**: `draftPicks` (core fields — `draftId`, `sequence`, `fpid`, `position`, `teamId`, `isKeeper`, `keeperStreak`, `teamAssignmentConfirmed`, `createdAt`; format-specific fields `price` vs `round`/`pickInRound`/`overallPick` sit side-by-side, exactly one set populated per format); `draftNominationTurns` (single "whose turn" pointer — soft suggestion for auction, authoritative for snake/linear); `seasonTeams`, `rosterPlayers`, `leagues`, `seasons` (minus costMode-specific keeper fields), `drafts` (status/startedAt/kind/historySource/sleeperSync*); players/projections/rankings/playerPoints/injuries/standardValues; `valueGaps`/`draftValues` caches; `preDraftInsights`; billing/OAuth tables.

**Functions**:
- `convex/draftType.ts`'s `resolveDraftType` — the one resolver every format-aware function/component calls
- `convex/draft/auth.ts` — `requireSeasonOwner`, `requireRealDraft`, `requireDraftOwner`, `requireDraftNotStarted`, `requireDraftStarted`
- `convex/draft/pickOrder.ts` — `rawStep`/`stepPickOrder`/`resolveTeamPositionInRound`, the shared rotation engine both `draftOrder.ts`/`pickSlots.ts`/`draftPick` (snake/linear) and `nominationOrder.ts` (auction) call into. **This math never gets duplicated client-side** — every frontend consumer reads pre-resolved data.
- `convex/draft/picks.ts` shared surface: `listDraftPicks(Public)`, `addKeeper` (explicit branch: auction needs `price`, snake/linear needs `round` + `resolveRoundConflict` — the model pattern for a properly-shared function), `removeKeeper`, `setKeeperStreak`, `setKeeperPrice` (⚠ not gated, see AUCTION.md Gaps), `setKeeperTeam` (explicit branch on round presence — recomputes the round when moving a keeper to a new team), `removePick`, `undoLastPick`
- `convex/draft/keeperRules.ts` — `setKeeperRules`/`setKeeperTierPlayers`, persists the whole mixed-shape `keeperRules` object without itself branching (readers discriminate via `costMode`)
- `convex/draft/teams.ts`, `lifecycle.ts`, `status.ts` (`syncDraftStatus`), `slots.ts`, `board.ts`, `tags.ts`, `tiers.ts`, `history.ts`, `manualHistory.ts`, `playerDetail.ts`, `lineupOptimizer.ts`, `customPlayers.ts`, `consistency.ts`, `insights.ts`
- **`convex/draft/reportCard.ts`** (whole file) + **`convex/gemini/reportSummary.ts`** — see [AUCTION.md](AUCTION.md)'s own entry for the full detail. Snake/linear runs two different value signals for two different jobs, not $ surplus: **grading** (surplusTotal, the letter grade, weighted 25% surplus/50% VOR/25% lineup via `SNAKE_GRADE_WEIGHTS`) uses a value-implied-round comparison (`ResolvedPick.round`/`impliedRound`/`roundSurplus`) ranked against the season's own VBD value curve, **excluding any VOR<=0 pick entirely** (`impliedRound` stays `null`) - `values` pools hundreds of ranked players per position, far deeper than any real roster, so the tied group at the $1/VOR-0 floor is enormous and would otherwise imply an absurdly late round for every replacement-level pick; **individual-pick callouts** (steals/reaches, each team's best/worst pick/keeper) display real blended market ADP (`ResolvedPick.adp`/`adpSurplus`), but only for a pick where `adpSurplus` and `roundSurplus` **agree on direction** (`calloutValueOf`/`calloutKeeperValueOf`) - neither raw ADP alone (too noisy at the back of a deep draft) nor the value curve alone is trustworthy for a single pick; requiring both to agree filters out exactly that tail-of-draft noise. AUCTION.md's entry has the full back-and-forth on why both exist. Neither needs separate keeper-value interpolation the way auction's `keeperEstimatedValue` does. `efficiencyDollarsPerVor` is null for this format.
- `convex/leagues.ts` — `listSeasons`, `getSeasonPublic`, `createLeague`, `updateSeason`, `importPreviousSeasonHistory` (`isRoundBased` branch decides `round` vs `price: player.price ?? 1` — depends on the caller supplying `previousDraftType`, which Sleeper does and Yahoo doesn't, see Gaps), `setUseKeepers`, `setDraftType` (dedicated post-creation format-correction mutation; pre-draft + zero-picks only), Sleeper/Yahoo link setters, `deleteLeague`
- `convex/draftValues.ts`, `convex/valueGaps.ts` — VBD/points/ADP-gap caches computed for every format (`points`/`positionRank`/`valueOverReplacement` are genuinely useful for snake/linear ranking too; `dollarValue` is auction-flavored but still computed unconditionally). `valueOverReplacement` is unclamped as of 2026-08-30 (can go negative below replacement) - `dollarValue` itself is unaffected, still floors at $1; see AUCTION.md's entry and `src/lib/valueRank.ts`'s below for why this specifically matters for snake/linear's "our rank."
- Sleeper/Yahoo sync (`convex/sleeper/league.ts`, `convex/yahoo/league.ts`), billing (`convex/billing/*`), Gemini (`convex/gemini/*` — `preDraftInsights.ts` branches its $-vs-market-by-tier signal to an ADP-vs-this-league's-rank-by-tier one for snake/linear, converted to rounds rather than dollars, but the keeper-scarcity/value-gap signals are already format-agnostic; `reportSummary.ts` branches its pick-facts formatting the same way `reportCard.ts` branches its grading — see that entry above), rankings/projections/players/scoring/positions

**Frontend**:
- `src/routes/index.tsx` (Dashboard), `route.tsx` (LeagueLayout — computes `isAuction` once, hides Budget tab / `DraftTopBar` accordingly), `settings.tsx` → `LeagueDetails.tsx` (heaviest branching page: draft-type control, salary-cap stat, `TeamsPanel`/`PickSlotsPanel` props), `keepers.tsx` → `KeepersTab.tsx` (computes `isSnakeOrLinear` once, threads into every keeper subcomponent), `league.tsx` → `LeagueTab.tsx`, `myTeam.tsx` → `MyTeamTab.tsx`, `players.tsx` (dispatches on `phase.isStarted`, **not** format - fine since both `PlayersTable` and `PlayersLeftTab` are themselves format-aware internally), `injuries.tsx`, `/reportCard/$leagueId` (fully format-agnostic), `/season/$leagueId/*` (post-draft, fully shared)
- `src/pages/DraftBoard/DraftBoard.tsx` — the format dispatcher itself (`isAuction` → early-return `SnakeDraftBoard`)
- `src/pages/Settings/PlayersTable.tsx` (pre-draft rankings table) and `src/pages/DraftRoom/PlayersLeftTab.tsx` (during-draft, table view only - bar view stays auction-flavored $/budget-match, see its own entry below) both compute `isAuction` once and thread it into their row components (`PlayerRow.tsx`/`PlayerRowMobile.tsx` pre-draft, `PlayerTableRow.tsx`/`PlayerTableRowMobile.tsx` in-draft): auction shows `$`/`vs. market` (`StandardValueLabel.tsx`) and a Nominate action; snake/linear shows `ADP`/`vs ADP` and a direct Draft action (`draftPick`, attributed to `getSnakeBoardPublic`'s on-the-clock team, falling back to the viewer's own team). `lib/valueRank.ts`'s `buildBlendedAdpByFpid`/`buildOurRankByFpid` compute the ADP/our-rank numbers once, shared by both tables (and `SnakeDraftTab.tsx`/`MobileSnakeDraft.tsx`, see their own entries above) so none of them ever disagree on the same player. Tier column is unchanged either way (already format-agnostic). Rank display differs between the two: pre-draft `PlayersTable.tsx` has one universal (not format-gated) desktop "Rank" column showing the row's position in the current sort (`index + 1` in `PlayerRow.tsx` - not a separately-fetched number), PLUS `AdpValueLabel.tsx`'s combined rank+diff cell in the separate "vs ADP" column for snake/linear specifically (`StandardValueLabel.tsx` for auction there instead) - `AdpValueLabel`'s own rank is real always-visible text now rather than a hover-only Tooltip, see AUCTION.md's own entry for the mobile-accessibility reasoning. In-draft `PlayerTableRow.tsx`/`PlayerTableRowMobile.tsx` instead give snake/linear a standalone, independently-sortable Rank column of their own (`SortKey`'s `"rank"`, PlayersLeftTab.tsx - auction has no equivalent column here, unlike the pre-draft table), positioned first - ahead of Player - with vs-ADP as its own separate diff column (`adpDiff`, computed inline, not `AdpValueLabel`) - user feedback, 2026-08-30, after the combined-cell version was fixed here but then flagged as the same "combining" problem on `SnakeDraftTab.tsx`/`MobileSnakeDraft.tsx` (see those entries) and asked to be split the same way on this table too. Auction's column count stays 8; snake/linear's is 9 (`PlayerTableRow.tsx`'s `AUCTION_COLUMN_COUNT`/`SNAKE_COLUMN_COUNT`, used for the expanded-actions row's `colSpan`). Both tables' default sort is "Rank" now (see AUCTION.md's entry above) - `PlayersTable.tsx` uses the same universal Rank column/key for both formats; `PlayersLeftTab.tsx` defaults to `"rank"` for snake/linear and `"dollar"` for auction (no Rank column there).
- `src/hooks/useFitScale.ts` (used by both TV boards), `useDraftPhase.ts`, `useSelfTeam.ts`
- `src/constants/leagueSettings.ts` — `DRAFT_TYPE_OPTIONS`, `DEFAULT_FORM`, `DEFAULT_KEEPER_RULES`
- `src/lib/featureFlags.ts` — `SNAKE_DRAFT_ENABLED`

**Critical invariant**: `costMode` (written by `KeeperRulesPanel.handleSave` as `isSnakeOrLinear ? "round" : "dollar"`) is the schema source of truth for $-vs-round keeper formula, but every frontend reader (`KeeperSearchForm`, `RecommendedKeepers`, `SleeperKeeperSuggestions`, `KeeperCardList`, `KeeperPriceCell`) independently re-derives `isSnakeOrLinear` from `settings.draftType` rather than reading `costMode`. **These two must never drift** — nothing enforces agreement if `draftType` and `keeperRules.costMode` are ever changed independently.

## Known gaps / landmines

1. ~~Report Card / AI recap silently ran (and produced garbage $ grades) for a completed snake/linear draft~~ — **resolved 2026-08-29**, see [AUCTION.md](AUCTION.md) Gap #4 and the Shared `reportCard.ts` entry above.
2. ~~**Budget-stat leakage**~~ — **resolved 2026-08-30** (all three originally-named offenders, user reports): `src/pages/DraftRoom/MyTeamTab.tsx` (the in-draft My Team tab) showed "$0 of $200 spent" and a wall of "plan $0" rows for every roster slot - `isAuction`-gates the $-spent stat and the whole "Where the money went" card, and `SlotTable.tsx` takes an `isAuction` prop so its second column shows `round.pickInRound` (via a new `draftedAt` computation) instead of a permanently-$0 Budget column for snake/linear. `src/pages/DraftRoom/LeagueTab.tsx` (the in-draft League/opponents overview) showed a "max bid: $200"-style figure per team (computed off `spent=$0` for everyone, always meaningless) and drove its per-team progress bar off `stats.remaining`/`stats.spent` ($ budget health, not roster fill) instead of the roster-fill count its own caption right below it already stated - `isAuction`-gates "N teams can match your $X", "max bid: $X", and "max $X/starter", and `fillPct` falls back to `teamPicks.length / stats.totalSlots` (actual roster fill - `totalSlots`/`openSlots` were already $-free) for snake/linear. `src/pages/Settings/SeasonSummary.tsx` (the "Seasons" history panel on the pre-draft Settings page, `LeagueDetails.tsx` → `SeasonHistoryPanel.tsx` — a read-only browser of a league's *past, already-completed* seasons for keeper continuity, not the deprecated `/season/*` in-season-tooling routes) showed a bare `$stats.spent` next to each team's name for a snake/linear historical season - `isAuction`-gates that one `<Text>`; its `fillPct` was already roster-fill-based (`teamPicks.length / slots.length`), and `TeamSlotDetail.tsx`'s per-pick `$price` suffix was already conditional on `pick.price !== undefined`, so neither needed a change. `LeagueDetails.tsx` (salary-cap stat), `DraftBoard.tsx` (`BudgetStats` vs. "N open"), and the Budget tab's visibility were already branched away from $ before this round of fixes.
3. **Yahoo import has no `draftType` detection**: `convex/yahoo/league.ts` only infers `isAuction: boolean` from whether a historical pick has a `cost`, and always resolves to `{ fpid, price }` shape. A Yahoo-imported league's prior season can never seed round-based keeper history — unlike Sleeper's import (`fetchPreviousSeasonPreview` detects the linked league's real historical `draftType`).
4. Live Sleeper draft sync (`convex/sleeper/draftSync.ts`, see [AUCTION.md](AUCTION.md)'s own entry) now supports snake/linear, but trusts the app's own `drafts.draftOrder`/`reversalRounds` to compute a synced pick's `pickInRound` (via `resolveTeamPositionInRound`), not Sleeper's raw slot numbers - the host must set the in-app Draft Order to match the real Sleeper draft's order *before* enabling sync, or picks land in the wrong board slot. Not yet tested against a real live snake/linear draft.
